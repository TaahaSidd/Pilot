Documentation

Welcome to Pilot. This guide covers everything from first-time setup to how the automation engine works under the hood. Setup takes under two minutes.

Pilot navigates Amity Online course dashboards autonomously handling reading modules, quiz resolution via Groq's Llama 3.3 70B, and feedback form completion across all your enrolled courses.

Open Source

Pilot is fully open source. Read the code, fork it, or contribute at github.com/TaahaSidd/Pilot.

Uses of Pilot

Pilot abstracts away the repetitive administrative layer of your student dashboard redirecting hours of manual clicking into automated pipelines.

Async Course Progression

Navigate linearly through course modules, reading assignments, and content pages automatically no manual clicking required.

AI Quiz Resolution

Pilot reads active quiz screens, structures them into payloads, and queries Groq's LLM to select correct answers using on-screen context.

Survey & Feedback Bypass

Auto-fills mandatory mid-module satisfaction cards, region selectors, and feedback forms so gated content unlocks instantly.

Multi-Course Sessions

Runs across all enrolled courses in a single session tracking progress and resuming from incomplete modules automatically.

Prerequisites

Before running Pilot, gather the following:

Amity Amigo Credentials

Your Amity student email (e.g. name@s.amity.edu) and portal password. Used to authenticate the browser session.

Groq API Key

Generate a key at console.groq.com. Free tier is sufficient for typical usage.

Python 3.8+

Verify with python --version. Any version from 3.8 onward works.

Git

Needed to clone the repository. Alternatively, download the ZIP from GitHub.

Quick Start

No hidden config files or plain-text credential storage. Pilot prompts you interactively at runtime.

Step 1 Clone and install

Terminal 
# Clone the repository
git clone https://github.com/TaahaSidd/Pilot.git
cd Pilot

# Install Python dependencies
pip install -r requirements.txt

# Install the Chromium browser binary
playwright install chromium

Step 2 — Run Pilot

Terminal 
python main.py

Step 3 — Enter credentials

Pilot will prompt you for three things in the terminal. Nothing is written to disk.

Interactive prompts 
[PILOT] Enter your Groq API key: gsk_••••••••••••••••••••••••
[PILOT] Enter student email: user@s.amity.edu
[PILOT] Enter portal password: ••••••••••••

# credentials held in session memory only
[OK] Spin-up validated. Launching browser...
Manual CAPTCHA step

After the browser opens and your credentials are filled, you'll need to manually complete the visual CAPTCHA on the Amigo login page. Once done, press Enter in the terminal to hand control to Pilot.

Step 4 — Let it run

Pilot scans your courses, identifies incomplete modules, and begins the automation loop. You'll see live progress in the terminal. When it finishes, a completion summary is printed for each course.

The Automation Loop

Once the browser session is active, Pilot works through your courses via a structured pipeline:

Phase 01

Course Scan

Pilot reads the course listing, checks completion percentages, and skips anything already at 100%.

Phase 02

Context Collection

During reading modules, Pilot scrapes visible text into short-term memory used as quiz context in the next phase.

Phase 03

Quiz & Feedback

Quizzes are resolved via Groq LLM inference. Feedback forms are auto-filled with compliant rating values.

Phase 04

Multi-Pass Unlock

After each pass, newly unlocked modules are picked up. Up to 10 passes run per session to fully clear gated content.

Quiz Solver

The internal QuizSolver reads the active multiple-choice quiz, structures the question and options into a payload, and sends it to Groq's Llama 3.3 70B model. The reading material accumulated during content passes is included as context.

inference_engine.py simplified 
import groq_cloud

# Payload assembled from on-screen quiz + reading buffer
payload = {
  "model": "llama-3.3-70b-specdec",
  "hardware": "Groq LPU Inference",
  "question": scraped_question,
  "options": scraped_options,
  "context": reading_material_buffer
}

answer = groq_cloud.infer(payload)
# ~240ms response time on average
→ Answer selected and submitted

Fail-safe guardrails

Grade protection is built in. The QuizSolver halts and skips submission if:

  • A question field is blank or undetected
  • The page layout doesn't match expected quiz structure
  • Fewer options are found than required

In these cases Pilot logs a warning and moves to the next module rather than submitting a bad answer.

Feedback Engine

The FeedbackSolver handles mandatory survey forms that gate progression. Without it, Pilot would stall at every feedback checkpoint.

The engine handles three field types:

  • Location selectors fills standard country and region dropdowns
  • Rating matrices selects high-tier scores (9/10) across all rating fields
  • Open text fields populates with human-like, minimum-length strings
Why 9/10?

Pilot uses 9/10 on rating forms to satisfy system requirements while maintaining a realistic, non-suspicious score distribution. Using 10/10 universally can sometimes flag automated sessions on certain portal implementations.
